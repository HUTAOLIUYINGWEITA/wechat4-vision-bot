# 架构说明

> 本文说明模块职责、数据流、运行期状态文件与日志字段。想先看「为什么这么设计」请读
> [`踩坑记录.md`](踩坑记录.md)；想先跑起来请看 [README](../README.md)。

## 1. 模块职责

| 文件 | 职责 | 关键边界 |
|---|---|---|
| `watcher.py` | **主程序**：主循环、配置/状态、日志、检测层（PrintWindow 抓图 + 未读/差分 + 任务栏兜底）、生成调度、护栏调度、调用 `reply.py`/`sendfile.py`、熔断、急停、远程指令状态机、CLI | 不自己注入键鼠；发送一律通过 `reply.py` 子进程 |
| `reply.py` | **执行层**：窗口枚举/切前台、`Ctrl+F` 搜索、整屏截图 + OCR 定位会话行、受控单击、标题校验、清空输入框、输入（`SendInput` / 剪贴板）、三重校验、`Enter`、前后截图、写 `reply_state.json` | 所有失败路径都 abort，**不按 Enter**；单次动作硬超时 20s |
| `sendfile.py` | 执行层扩展：把文件放进剪贴板（`CF_HDROP`）→ `Ctrl+V` → 等待附件预览 → 可选 caption → `Enter`；敏感文件名拒绝发送 | 只读源文件；复用 `reply.py` 的打开会话/校验逻辑 |
| `genreply.py` | **生成层**：读 `.credentials.json` + `persona.txt`，进程内 `POST {baseUrl}/chat/completions`，清洗 + 禁用词检查；`apiKey` 全程 `sk-***` 脱敏 | 不碰微信；失败返回 `ok=False`，不抛到主循环 |
| `sendguard.py` | **护栏层**：白名单、同会话最小间隔、连续条数上限 + 暂停、同句去重、发送记录落盘 | 纯判断/记录，不执行动作 |
| `busyguard.py` | **忙闲守护**：前台进程是否游戏（只按进程名）、静默时段、每小时速率 | 只读查询，绝不注入 |
| `toggle.ps1` | 总开关：`on`/`off`/`stop`/`panic`/`start`/`status`；pid 命令行校验；写 config 时保持 UTF-8 无 BOM | 只杀命令行含 `watcher.py` 的进程 |
| `toggle-ui.ps1` | 交互式数字菜单，调用 `toggle.ps1` | — |
| `xiaoxiao-ear-toggle.cmd` | 双击入口（用 `powershell -File` 跑 `toggle-ui.ps1`） | 纯 ASCII + CRLF |
| `tools/setup_password.py` | 生成/更新远程指令两级密码的 `salt`+`sha256`，写 `config.json`（无 BOM） | 不回显明文；算法与 `watcher.sha256_pwd()` 一致 |
| `selftest_rows.py` | 会话行选择精度离线回归（构造用例 + 可选真实截图语料） | 不发消息、不碰屏幕 |
| `selftest_stage1.py` | 输入校验/面板判别/熔断 mock/三处急停/`py_compile` 离线自测 | 不碰屏幕（只读 `GetAsyncKeyState`） |

## 2. 数据流

### 2.1 自动回复主链路（LLM 生成 → 微信发送）

```
[每 intervalSeconds 秒一轮]
  ├─ 0. 看 STOP 文件？有 → 立即退出
  ├─ 1. 热键急停检测（GetAsyncKeyState Ctrl+Alt+Shift+S）
  ├─ 2. 检测层：枚举 Weixin.exe 顶层窗口 → 选主窗口 → PrintWindow 抓图
  │      ├─ 会话列表未读红点检测
  │      ├─ 会话列表文本区「稳定基线」差分（settleScans 轮稳定才认账）
  │      └─ （窗口最小化时）任务栏层：抓任务栏 → 定绿色微信图标 → 角标红点
  ├─ 3. 命中新未读 → 存截图 screenshots/wechat-*.png，写 signal.json
  ├─ 4. 白名单命中？未命中/黑名单 → 只记日志
  ├─ 5. 远程指令检查（_remote_forward，见 2.2）
  │      ├─ 微信口令急停（触发词 + 急停/停止）→ 写 STOP 退出
  │      └─ 远程指令状态机命中 → 转告本地 Agent（remote.enabled=true 时）
  ├─ 6. 生成层：读取对方最近消息（可选 OCR）→ genreply.generate()
  ├─ 7. 护栏层：sendguard.check() → 拒绝则 skip（限流/去重/连续条数/白名单）
  ├─ 8. 执行层：subprocess 调用 reply.py --chat X --text Y
  │      └─ reply.py 成功后追加 reply_state.json["sent"]
  ├─ 9. 等 reply_state.json 出现新记录才算「已处理」→ 写 processed_fingerprint
  │      超时（replyConfirmTimeoutSeconds）→ 不算已处理，按失败重试
  ├─ 10. 失败次数累计 → breaker 连续 3 次失败 → 写 STOP + breaker_tripped.json + 退出
  └─ 11. 写 state.json（指纹/重试/唤醒次数等）
```

关键设计：**「发送确认」而不是「调用成功」才算处理完成**。`reply.py` 写进 `reply_state.json`
的 `sent` 记录是唯一事实来源；这样 watcher 崩溃/超时后不会把没发出去的消息误标成已处理。

### 2.2 远程指令链路（默认关闭）

```
白名单来信（含触发词）
  → panic 关键词？ → 写 STOP + 退出（不等密码）
  → remote.enabled=false → 走普通闲聊回复
  → remote_plan() 状态机（纯函数，可离线自测）
      ├─ 无 pending、无密码 → 建 pending，回「需要密码」（L1/L2 提示）
      ├─ pending + 密码正确 → 检查 L1 高危词（L1 遇高危动作 → 要 L2 密码）
      ├─ 密码错误累计 → 达到 maxWrongAttempts → lockout
      └─ 通过 → 组装 prompt（授权级别 + allow 清单 + 来信原文脱敏）
  → 投递到本地 Agent 会话（remote.targetSessionId / targetSessionTitle）
  → 审计写 logs/remote-YYYYMMDD.jsonl
```

> 本项目只负责「把微信消息变成一次对本地 Agent 的 prompt 投递」；Agent 本身不在本仓库内。
> 投递端当前适配本地 DeepSeek Harness（DSH）的 Web API：读取 `$DSH_HOME/.credentials.yaml`
> 的 browser-session 密钥，本地铸造 Cookie 后调 `session/prompt`（`wake.baseUrl` 默认
> `http://127.0.0.1:19387`）。没有 DSH 环境时该功能只会得到 `wake_fail` 回执——
> 自动回复主链路不依赖它，保持 `remote.enabled=false` 即可。

## 3. 配置文件（`config.json`）

从 `config.example.json` 复制而来，**不进仓库**。分段落：

| 段 | 作用 |
|---|---|
| 顶层 `enabled` / `autoSend` | 总开关 / 是否真发送 |
| `whitelist` / `blacklist` | 会话白名单 / 黑名单（OCR 容错匹配见 `whitelistMatch`） |
| `guard` | 限流/去重/连续条数（护栏核心） |
| `busyGuard` | 游戏进程名单 + 静默时段 + 速率 |
| `detect` | 窗口类名、抓图模式、红点阈值、任务栏兜底开关 |
| `ocr` | tesseract 路径（空=自动探测）、语言、超时 |
| `gen` | 模型参数（maxTokens ≤120）、人设文件、凭据文件、禁用词、`testHooks` |
| `breaker` | 连续失败阈值（默认 3） |
| `panic` | 急停热键、微信急停关键词、是否弹气泡 |
| `wake` | 历史遗留的「唤醒 Agent」配置（默认关闭，代码保留仅兼容） |
| `remote` | 远程指令：两级密码哈希、允许动作、pending TTL、锁定、审计、目标 Agent 会话 |
| `reply` | 发送后是否还原前台/剪贴板（默认都 false） |

## 4. 运行期状态文件（全部被 `.gitignore` 忽略）

| 文件 | 写入方 | 内容 | 说明 |
|---|---|---|---|
| `watcher.lock` | watcher / toggle.ps1 | 进程 pid 文本 | 仅作提示；杀进程前必须校验命令行含 `watcher.py` |
| `STOP` | toggle.ps1 / watcher（急停/熔断） | 一行原因文本 | **存在即急停**；watcher 启动/每轮看到就退出；`toggle.ps1 on` 才删 |
| `state.json` | watcher | `processed_fingerprint` / `processed_at` / `processed_unread` / `processed_history`（最近 20 条）、`retry_pending`（待重试 fp/次数）、`awaiting_send`（等发送确认的 fp/since/timeout）、`gave_up`、`wake_times`、`row_name_cache`（会话行名缓存，最近 200） | 删掉它 = 忘记"哪些消息已处理"（可能重复回，谨慎） |
| `reply_state.json` | reply.py | `{"sent": [ ... 最近 50 条 ... ]}`，每条含 `chat` / `display` / `text` / `ts` / `at` / `before` / `opened` / `typed` / `after`（截图路径）/ `pixel_diff` / `elapsed` / `mouse_events` / `key_events` / `hard_timeout` | watcher 靠它确认"真的发出去了" |
| `guard_state.json` | sendguard.py | 每个会话的 `lastSentAt` / `consecutive` / `totalSent` / `recentTexts` / `lastFingerprint` 等 | 限流/去重状态 |
| `breaker_state.json` | watcher | `consecutiveFailures` / `lastFailureAt` / `lastReason` / `lastSuccessAt` | 连续失败计数；成功一次清零 |
| `breaker_tripped.json` | watcher | `trippedAt` / `reason` / `consecutiveFailures` / `threshold` / `source` / `stopFile` 等 | 熔断记录（保留供排查，不自启） |
| `signal.json` | watcher | 最近一次检测信号：`detectedAtLocal` / `reason` / 未读 badge 信息 / `screenshot` 路径 / 当时的 `autoSend`、`whitelist`、`blacklist`、`quietHours` 等判定上下文 | 调试"为什么判定命中/不命中"的第一现场 |
| `remote_pending.json` | watcher | `{"pending": {chat: {...挑战/时间/尝试次数}}, "lockouts": {chat: 解锁时间}}` | 远程指令挑战-应答状态，重启不丢 |
| `remote_notify_state.json` | watcher | 每个 `chat+reason` 的提醒时间戳 | 失败提醒冷却（默认 600s） |
| `tmp-inject-unread.json` | 你（测试钩子） | 造一条白名单未读的测试数据 | 仅 `gen.testHooks=true` 时生效，用完删 |
| `logs/`、`screenshots/`、`tmp-ocr/` | 各模块 | 见下 | 均为本地私人数据，不提交 |

## 5. 日志字段说明

### 5.1 `logs/watchdog-YYYYMMDD.log`（主日志，纯文本行）

```
2026-10-27 20:05:27 [INFO] [PANIC] source=hotkey ...      ← 时间 [级别] 消息
```

- 级别：`INFO` / `WARN` / `ERROR`
- 常见前缀：`[GEN]`（生成）、`[GUARD]`（护栏）、`[REMOTE]`（远程指令）、`[BREAKER]`（熔断）、
  `[PANIC]`（急停/熔断）、`[ALERT]`（失败告警）、`[TEST]`（测试钩子）
- 日志里出现来信原文的位置都会被 `mask_sensitive()` 处理：密码形态 / 6 位以上连续数字一律打码。

### 5.2 `logs/sent-YYYYMMDD.jsonl`（每次成功发送一行）

| 字段 | 含义 |
|---|---|
| `at` / `ts` | 时间（可读字符串 / epoch 秒） |
| `chat` | 会话显示名 |
| `text` | 实际发出去的回复正文 |
| `fingerprint` | 触发这次回复的未读指纹 |
| `consecutive` | 该会话连续发送计数 |
| `perChatMinIntervalSeconds` | 当时的限流配置（审计用） |
| `display` / `reason` / `guard` / `gen` / `model` / `latencyMs` / `before` / `after` / `elapsed` / `mouse_events` / `key_events` | 可选扩展字段（来源/护栏判定/生成信息/截图路径/耗时/注入事件数） |

### 5.3 `logs/panic-YYYYMMDD.jsonl`（急停审计，每次急停一行）

```json
{"at": "2026-10-27 20:05:27", "source": "hotkey|wechat-command|shortcut-toggle.ps1|breaker", "detail": "..."}
```

### 5.4 `logs/remote-YYYYMMDD.jsonl`（远程指令审计）

| 字段 | 含义 |
|---|---|
| `chat` / `level` | 来信会话 / 判定级别（L1/L2） |
| `passwordOk` / `attempts` | 密码是否通过 / 当前尝试次数 |
| `incoming` | 来信原文（**已脱敏**：密码形态打码） |
| `targetSessionId` / `promptChars` | 目标 Agent 会话 / 转告 prompt 长度 |
| `action` | `chat_only` / `need_password` / `wrong_password` / `lockout` / `wake_ok` / `wake_fail` |
| `replyOk` / `rpcError` / `latencyMs` / `errorReplyOk` | 回执发送结果 / RPC 错误 / 耗时 |

### 5.5 `logs/reply-failures-YYYYMMDD.jsonl`（回复失败记录）

时间 / 目标会话 / 原因（如 `row-approximate`、`title-verify-failed`、`type-verify-failed`、
`wechat-window-lost`、`search-layer-not-opened`、`user-active`、`busy`）/ 建议 / 降级提醒会话。

### 5.6 `logs/sendfile-YYYYMMDD.jsonl`（发文件审计）

时间 / 会话 / 文件路径 / 敏感拦截结果 / 各阶段（`guard` → `open` → `paste` → `send`）结果。

## 6. 执行层（reply.py）内部流程与失败原因

```
枚举窗口 → 选主窗口（可见、尺寸合理，否则 wechat-window-* abort）
  → busyguard.evaluate()（前台游戏 → skip busy；静默/速率 → skip）
  → 切前台：AttachThreadInput（零键鼠）→ 失败才 ALT 技巧（必释放 ALT）
  → Ctrl+F → 输入会话名
  → 整屏截图（前台不是微信 → abort）→ 面板类型判别：
       dropdown（搜索下拉）/ conversation-list（其实是会话列表）/ unknown
  → OCR 行（词级聚类，2.0x 放大 + psm6/11 两遍 + 候选行 psm7 精读）
  → 行类型判定：彩色头像 = 会话行；灰色放大镜 = 聊天记录/命令条目（不参与）
  → select_target_row()：exact 唯一 / 近似唯一（覆盖率+精确率+领先第二名）→ 否则 abort
  → 受控单击行中心 → OCR 标题校验（exact / 近似唯一 / 群聊 (N) 类型校验）
  → 清空输入框（Ctrl+A + Delete）→ 输入：
       长文本/含全角标点 → 剪贴板 Ctrl+V；短文本 → SendInput；互兜底重试一次
  → 三重校验（input_text_metrics）→ 不过则 type-verify-failed abort（不按 Enter）
  → 发送前复检（前台非游戏 / 用户没动键鼠 / 标题没变）
  → Enter → 发送后截图 + 像素差 + 输入框清空校验
  → 成功：追加 reply_state.json.sent；失败：退出码 + 原因
```

常见 abort `reason` 及含义：

| reason | 含义 | 处理 |
|---|---|---|
| `wechat-window-not-found` / `-minimized` / `-hidden-to-tray` | 微信窗口不可用 | 把微信主窗口恢复出来再试 |
| `search-layer-not-opened` | Ctrl+F 后没确证搜索层 | 看日志/截图；是不是快捷键被占用 |
| `dropdown-*` / `row-not-found` / `row-approximate` | 下拉里定位不到可靠会话行 | 检查会话名/字号/OCR 是否正常 |
| `row-ambiguous` / `row-group-mismatch` | 命中多个候选/群聊类型不符 | 加固白名单名字（越独特越好） |
| `title-verify-failed` | 点开后标题不符 | 正常安全 abort，不会发错人 |
| `type-verify-failed` | 输入内容校验不过（丢字/乱码） | 正常安全 abort，不按 Enter |
| `user-active` / `busy` | 用户在操作 / 前台是游戏 | 正常安全 abort |
| `wechat-window-lost` | Esc/点击后窗口消失 | 最高优先级告警，检查微信是否被收进托盘 |
| `tesseract-missing` | 找不到 tesseract / chi_sim | 按 README 安装并验证 `--list-langs` |

## 7. 时间/一致性约定

- 所有时间默认本地时区；`state.json` / `reply_state.json` 里的 epoch 秒用于跨进程比较。
- `config.json` 热加载：watcher 每轮比对 mtime，改动后下一轮自动生效（但 `enabled/autoSend`
  改完建议用 `toggle.ps1 status` 确认进程与配置一致）。
- 单实例保护：`watcher.lock` + 已存在进程扫描；`toggle.ps1` 启动前会先找同命令行进程，避免跑两份。
